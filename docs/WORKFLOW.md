# Pi 工作纪律

## 循环熔断

- 同一操作连续失败 ≥3 次 → 立即停，换策略
- 任何操作循环 >10 次 → 主动警告自己换策略
- 任何操作循环 >20 次 → 记录错误 + 停止 + 询问用户

## 工具优先级

1. `ctx_read` → 2. `ctx_search`/`ctx_grep` → 3. `ctx_patch`
2. 能用轻的不升级重

## 完成判定

- 代码要编译 + 测试
- 分析要有 file:line 证据链
- 不凭感觉交付

## 状态检查点

- 关键步骤写 daily memory
- 任务结束写 session summary
- 落盘后确认路径

## 压缩策略

- 上下文占用 >60K → 主动触发 compress
- 压缩前先 memory_write 保存关键状态
- 保护：用户消息、代码块、错误信息不被压缩

## think 调用规则

- 简单任务: 0-1 次
- 复杂任务: 2-3 次
- 超 3 次必须说明理由
- **禁止循环 think**（连续 think >3 次未调用工具 → 立即熔断）

## guardrail 处理

ACP guardrail 强制阻止时：

1. 用 glm-4.7 分析上下文
2. 确认安全后切回 agnes-2.5-flash 执行下一步

## 记忆保存位置

| 位置 | 用途 |
| ------ | ------ |
| `{HOME}/.pi/agent/memory/MEMORY.md` | 持久规则与偏好 |
| `daily/<YYYY-MM-DD>.md` | 每日日志 |
| `{DATA_DIR}\日志\会话记忆.md` | 完整会话记录（永久保存） |

## 退出保存强制规则

每次会话结束（用户说"保存退出"、"完了"等）前：

1. 将本次完整对话追加到 `{DATA_DIR}\日志\会话记忆.md`
2. 包含时间戳、用户请求、AI 响应、完成工作、关键路径
3. 优先级高于压缩

## 错误库 & 计划库

1. 先查库（命中照办/复用）
2. 没命中再解决
3. 解决后回填

## 复杂度判断

- **所有任务** → 先出计划存 `{DATA_DIR}\计划库\` → 等确认 → 执行 → 追加记录
