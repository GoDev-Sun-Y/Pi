# Pi-Work-Mode 部署指南

> 本文档写给「要动手部署的人或 AI」。读完可以直接照着执行，不需要额外背景知识。
>
> 文档位置：`Pi-Work-Mode\docs\部署指南.md`（仓库内，随仓库一起传播）
> 文中 `<仓库路径>` 指本仓库在本机的实际位置，执行前请替换。

## 0. 给 AI 的执行说明

如果你是一个 AI agent，用户把这份文档交给你，请按下面的方式工作：

1. **先读第 1 节**，用大白话告诉用户「这个东西是干什么的」，不要直接开始装。
2. **核对第 2 节的环境清单**，用命令实测，把缺的项告诉用户。
3. **按第 3 节顺序执行**。第 3.3 节（正式安装）会弹 UAC 且会写用户主目录和 `C:\PiData`，
   **执行前必须先向用户确认数据目录**。
4. **每完成一个阶段就跑一次第 4 节的验证**，不要最后一次性验证。
5. **第 6 节是禁止事项**，踩了会坏数据或污染仓库，务必先读。

你可以自由修改命令里的数据目录路径，但不要改动仓库里的脚本逻辑——那些脚本已经过实测。

## 1. 这是什么

### 1.1 先说 Pi 是什么

**Pi 是一个跑在你自己电脑命令行里的 AI 编程助手**（术语叫 agent harness）。你在终端敲 `pi`，
它启动，然后你可以像跟人对话一样让它读代码、改文件、跑命令。

它和你熟悉的网页版 AI（ChatGPT、Claude 网页版）的区别：

| | 网页版 AI | Pi（本地 agent） |
| --- | --- | --- |
| 运行位置 | 别人的服务器 | 你自己的电脑 |
| 能不能直接动你的文件 | 不能 | **能**，直接读写本地文件、执行命令 |
| 有没有记忆 | 关掉网页就忘 | 记忆存在本地文件，跨会话保留 |
| 谁能定制它的行为 | 官方 | 你自己，配置文件随便改 |

官方资料：`https://pi.dev` ／ 源码 `https://github.com/earendil-works/pi`

### 1.2 这个配置包加了什么

**Pi 本体是「一个空壳 + 一堆接口」，默认行为很朴素。**
`Pi-Work-Mode` 这个包做的事情是：**把一套已经调好的工作习惯，打包成可以直接装进 Pi 的配置。**

装完之后，你的 Pi 从「一个能干活的助手」变成「一个按你规则干活的助手」：

| 装之前 | 装之后 |
| --- | --- |
| 想让它干什么得每次重复交代 | 有固定的人格和沟通风格（`AGENTS.md` 里写死的规则） |
| 所有工具一直挂着，吃光上下文 | **按需加载**：平时只挂轻量工具，要联网/分析代码/写方案时自动切换 |
| 犯错会一直重试 | 同一操作失败 3 次自动熔断，不再空转 |
| 上下文满了就丢历史 | 超过 60K 先存进记忆再压缩 |
| 跨会话失忆 | 三层记忆 + 向量语义检索，能记住你说过的话 |
| 有复杂任务只能自己串行做 | 可以把任务拆给子代理并行处理 |

### 1.3 一句话总结

> **Pi = 本地 AI 助手引擎。**
> **Pi-Work-Mode = 给这个引擎装的一套「工作规范 + 记忆系统 + 工具调度器」。**

## 2. 部署前的环境要求

### 2.1 需要什么

| 依赖 | 最低版本 | 必须吗 | 用途 |
| --- | --- | --- | --- |
| Node.js | ≥ 22.19.0 | **必须** | Pi 本体运行环境 |
| npm | 随 Node | **必须** | 安装 Pi 与扩展 |
| Git | ≥ 2.40 | **必须** | 拉取扩展。安装脚本硬依赖，缺了会在第 1 步检测时直接退出 |
| Python | ≥ 3.10 | 可选 | 记忆管理（不用记忆可以不装） |
| Docker | 任意近期版本 | 可选 | 跑 Qdrant 向量库（不用记忆可以不装） |
| Ollama | 最新 | 可选 | 本地 embedding 模型（不用记忆可以不装） |

### 2.2 参考：一套实测通过的环境（2026-09-12，供对照）

| 项目 | 实测结果 | 结论 |
| --- | --- | --- |
| Node.js | v22.22.2 | 满足（要求 ≥ 22.19.0） |
| npm | 10.9.7 | 满足 |
| Python | 3.12.1 | 满足 |
| Git | 2.52.0.windows.1 | 满足 |
| Docker | 29.5.3（守护进程需手动启动） | 满足，用前先起 Docker Desktop |
| Ollama | 未安装 | 需要时再装 |

> **关于 `pi` 命令的验证姿势**：Pi 的启动器是 `pi.cmd`，
> 所以 PowerShell / CMD 下输入 `pi` 能跑，但 **Git Bash 里 `which pi` 会找不到**
> ——因为 Git Bash 默认不认 `.cmd`，这是正常现象，不代表 Pi 没装。
> 要验证，用 `powershell -c "pi --version"` 而不是 Git Bash 的 `which`。

> **关于 `~/.pi/agent/`**：如果这台机器以前用过 Pi，这个目录里会有旧痕迹
> （`sessions/`、旧 `settings.json`、旧规则文档）。
> 部署脚本会**备份并合并**这里的配置，不会直接抹掉。
> 想完全不碰它做一次干净测试，用 `-AgentDir` 或环境变量 `PI_CODING_AGENT_DIR` 重定向。

### 2.3 自查命令

```powershell
node --version      # 需要 >= v22.19.0
npm --version
git --version
python --version    # 可选
docker --version    # 可选
pi --version        # 需要能打印版本号
```

> 在 Git Bash 里请用 `powershell -c "pi --version"`；直接敲 `which pi` 会误报"未安装"。

## 3. 部署步骤

一共 6 个阶段。**1 → 2 → 3 → 4 是主干**，5、6 按需。

### 3.1 阶段一：安装 Pi 本体（必做）

Pi 本体是引擎本身，和 `Pi-Work-Mode` 的配置内容无关。

**推荐做法：用仓库自带的脚本一键装。**

```powershell
cd "<仓库路径>"
powershell -ExecutionPolicy Bypass -File scripts\install-pi.ps1
```

默认装到 `<仓库>\.pi-runtime\`，**自包含**：不写全局 npm 目录、不改 PATH、不动用户主目录。
装完在 `.pi-runtime\` 下生成 `pi.cmd` / `pi.ps1` / `pi` 三个启动器，
路径全部相对定位、不硬编码，可整体拷贝到别的机器直接用。

> ⚠️ **必须知道的一点**：自包含安装**不会**让 `pi` 成为全局命令。
> 在把 `.pi-runtime` 加进 PATH 之前，直接敲 `pi` 会提示「不是内部或外部命令」——
> 这是**预期行为，不是安装失败**。
> 本文后续凡出现 `pi xxx`，在还没加 PATH 时请替换成 `"<仓库路径>\.pi-runtime\pi.cmd" xxx`，
> 或者先按下面的方法把目录加进 PATH。

常用参数：

| 参数 | 说明 |
| --- | --- |
| （不填） | 装到 `<仓库>\.pi-runtime` |
| `-InstallDir "D:\Pi"` | 装到指定目录 |
| `-Global` | 装到 npm 全局目录（等价官方 `npm install -g` 方式） |
| `-Version 0.85.1` | 钉死版本，默认 `latest` |
| `-Force` | 已装也重装 |
| `-AgentDir "<路径>"` | 验证时使用的配置目录（隔离用，不影响 `~\.pi\agent`） |
| `-DryRun` | 干跑预览，不做任何改动 |
| `-Uninstall` | 卸载 |

验证：

```powershell
& "<仓库路径>\.pi-runtime\pi.ps1" --version
```

能打印版本号就成了。**如果这一步失败，后面全部没意义**，先解决网络或权限问题。

**想让 `pi` 命令全局可用**，把 `.pi-runtime` 加进 PATH（脚本刻意不自动改 PATH）：

```powershell
[System.Environment]::SetEnvironmentVariable(
  "Path", [System.Environment]::GetEnvironmentVariable("Path","User") + ";<仓库路径>\.pi-runtime", "User")
```

> **手动方式（官方）**：`npm install -g --ignore-scripts @earendil-works/pi-coding-agent`
> Windows 也可用官方脚本 `powershell -c "irm https://pi.dev/install.ps1 | iex"`。
> `--ignore-scripts` 是官方推荐参数，用来跳过依赖包的生命周期脚本，别省。
> 要求 Node.js ≥ 22.19.0。
>
> **为什么不默认用官方全局安装？** 全局安装会写进 npm 全局目录（如
> `C:\Users\<你>\AppData\Roaming\npm` 或 Node 安装目录），属于对系统的改动，
> 权限不足时还会弹 UAC。装到仓库内的 `.pi-runtime` 则完全自包含、随时可整目录删除。
> 需要全局可用时再用 `-Global` 或手动把目录加进 PATH。

### 3.2 阶段二：干跑预览（必做，零风险）

干跑不会创建任何目录、不会改任何文件，只打印它打算做什么。

```powershell
cd "<仓库路径>"

powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -DataDir "C:\PiData" -DryRun
```

**先确认 `-DataDir` 这个路径。** 它是脚本要创建的「数据目录」，将来会存日志、错误库、向量数据库文件。
建议放在空间充足的盘，默认值用 `C:\PiData` 即可。

预期看到「第 0 步」到「第 7 步」全部打印出来，每一步前面带 `[干跑]` 标记，且没有 `[失败]`。

### 3.3 阶段三：正式安装（会弹 UAC）

```powershell
cd "<仓库路径>"

powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -DataDir "C:\PiData"
```

**要点：**

- 脚本检测到非管理员时会**弹 UAC 提权框，必须点「是」**，否则安装中断。
  如果你确定依赖（Node / Python / Git / Docker）都已就绪、不需要装系统级组件，
  加 `-NoElevate` 可跳过提权、避免 UAC 弹窗。
- 提权后的窗口是新开的，命令参数会自动透传，你不需要重新输一遍。
- 安装过程需要联网。**7 个扩展里 6 个从 npm 拉取，1 个（`pi-custom-packages`）来自 GitHub**，
  比旧版（全部 `git clone`）可靠得多；任何扩展失败只打印 `[警告]`，不影响主体安装。

**常用参数：**

| 参数 | 说明 |
| --- | --- |
| `-DataDir "<路径>"` | 数据目录（日志 / 错误库 / 向量库） |
| `-PiPrefix "<路径>"` | Pi 本体安装目录，默认 `<仓库>\.pi-runtime` |
| `-SkipPi` | 跳过 Pi 本体安装（已有 Pi 时用） |
| `-SkipExtensions` | 跳过扩展安装（离线环境） |
| `-SkipGitExtension` | 只跳过那个需要连 GitHub 的扩展（其余 6 个照装） |
| `-GitExtensionTimeoutSec <秒>` | 该扩展的超时时间，默认 180，超时自动换镜像重试、再失败就跳过 |
| `-SkipQdrant` | 跳过 Qdrant 向量库 |
| `-SkipOllama` | 跳过 Ollama 安装 |
| `-SkipPythonDeps` | 跳过 pip 依赖（qdrant-client） |
| `-AgentDir "<路径>"` | 改写配置目录（默认 `~\.pi\agent`），隔离测试用 |
| `-NoElevate` | 不自动请求 UAC 提权 |
| `-DryRun` | 干跑预览，不做任何改动 |

**这一步会做什么：**

| 步骤 | 动作 |
| --- | --- |
| 第 0 步 | 确定数据目录 |
| 第 1 步 | 检测 Node / Python / Git / Docker |
| 第 2 步 | 自动安装缺失的环境 |
| **第 2b 步** | **安装 Pi 本体**（调用 `scripts\install-pi.ps1`） |
| 第 3 步 | 创建目录结构 |
| 第 4 步 | 部署配置文件、规则文档，以及 `/preset` 扩展与预设定义 |
| 第 5 步 | 安装扩展（6 个走 `pi install npm:xxx`，1 个走 `pi install git:...`） |
| 第 6 步 | 启动 Qdrant 向量库（Docker 可用时） |
| 第 7 步 | 验证安装结果 |
| 第 7b 步 | 安装 Ollama 与本地 embedding 模型 |
| 第 7c 步 | 提示配置 API Key |

#### 卡住不动怎么办（三个历史高发点）

安装过程中**任何一步长时间不动，都可以 Ctrl+C 中断**——前面完成的步骤不会丢失，
卡住的又都是可选组件。三个最容易卡的地方及对策：

| 卡在 | 原因 | 对策 |
| --- | --- | --- |
| `pi install git:github.com/...` | 这是唯一需要直连 GitHub 的扩展，国内网络易超时 | 脚本已内置 180 秒超时 + 自动换镜像重试 + 最终跳过。不想试就加 `-SkipGitExtension` |
| `正在安装 Python 依赖` | pip 直连国外 PyPI | 脚本已默认走清华镜像并显示 pip 输出；仍卡就 Ctrl+C，手动 `pip install -i https://pypi.tuna.tsinghua.edu.cn/simple qdrant-client`，重跑时加 `-SkipPythonDeps` |
| `下载 Ollama 安装包` | 安装包**约 1.5GB** 且走国外源 | 脚本会显示 `已下载/总量/速度/剩余时间`。实在慢就 Ctrl+C，手动双击 `%TEMP%\OllamaSetup.exe` 安装（已下载的部分不浪费），跳过注册页后重跑 `install_ollama.ps1` |

> Ollama 装完会弹注册页，点最下方 **"No thanks, I'll use Ollama locally"** 即可——
> 它是本地运行的，不需要账号。

**会产生/改动的文件：**

```
<仓库路径>\.pi-runtime\               ← Pi 本体（自包含，可整目录删除）
├── node_modules\                     ←   Pi 的代码
├── pi.cmd / pi.ps1 / pi              ←   三个启动器

~/.pi/agent/                          ← Pi 的配置主目录
├── AGENTS.md                         ← 【关键】主规则，Pi 启动时读这里
├── WORKFLOW.md                       ← 工作纪律
├── SUBAGENT_PROTOCOL.md              ← 子代理协作协议
├── 规则索引卡.md                      ← 快速参考卡
├── settings.json                     ← 合并写入，原有键保留；packages 列表存这里
├── models-store.json                 ← 模型路由表（原文件会先备份）
├── presets.json                      ← /preset 预设定义（工具集 + 注入指令）
├── npm\                              ← pi install 装的 npm 扩展
├── git\                              ← pi install 装的 git 扩展
└── extensions\
    └── preset.ts                     ← 提供 /preset 命令的扩展（Pi 官方示例）

C:\PiData\                            ← 数据目录
├── 文档\reference\                    ← 规则文档副本
├── 脚本\                              ← 脚本副本
├── 日志\
├── 错误库\
├── 计划库\
└── qdrant_storage\                   ← 向量库数据
```

> **重要**：`AGENTS.md` 必须落在 `~/.pi/agent/` 下，Pi 才会在启动时加载它。
> 只放进 `C:\PiData\文档\` 是**无效**的——Pi 不会去那里读规则。
> 现行脚本已经同时部署到两个位置，不用你手动处理。

> **配置目录可重定向**：Pi 官方支持环境变量 `PI_CODING_AGENT_DIR` 指定配置目录。
> 设了它，上表里的 `~/.pi/agent/` 就会换成你指定的路径，用户主目录完全不写。
> 这是做隔离测试的关键——`setup.ps1 -AgentDir` 内部就是设置这个变量。

### 3.4 阶段四：重启后补跑一次

如果第 2 步装了 Docker Desktop，**需要重启电脑**，然后重跑同一条命令：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -DataDir "C:\PiData"
```

脚本是幂等的（已存在的目录/文件/扩展会跳过），重跑不会重复安装。

### 3.5 阶段五：配置模型密钥（必做，否则 Pi 无法对话）

Pi 是外壳，模型才是"大脑"。你必须给它一个模型提供方的钥匙，否则启动后会提示
`No models available`。下面三种方案任选其一。

> ⚠️ **改完环境变量必须新开一个终端窗口**，已打开的窗口读不到新值。
> 这是本流程最容易踩的坑——如果 Pi 看不到模型，八成是窗口没换。

#### 方案 A：Agnes（本包默认，国际站）

```powershell
[System.Environment]::SetEnvironmentVariable("AGNES_API_KEY", "sk-xxx", "User")
```

密钥申请：`https://agnes-ai.com`

**Agnes 有国际/国内两个站点，钥匙必须三处对齐，错一个就是 401：**

| 注册站点 | Provider | 端点 | 环境变量 |
| --- | --- | --- | --- |
| agnes-ai.com（国际） | `agnes` | `https://apihub.agnes-ai.com/v1` | `AGNES_API_KEY` |
| agnes-ai.cn（国内） | `agnes-cn` | `https://api.agnes-ai.cn/v1` | `AGNES_CN_API_KEY` |

常见翻车：**在国际站注册，却把钥匙存进 `AGNES_CN_API_KEY`** —— 请求会带着
国际站的钥匙去敲国内站的门，必然 `401 无效的令牌`。

> 注：旧版文档写的 `api.sapiens.ai` 已不作为推荐入口，以官网为准。

#### 方案 B：智谱 GLM（国内推荐，Pi 内置 zai provider）

```powershell
[System.Environment]::SetEnvironmentVariable("ZAI_API_KEY", "完整key", "User")
```

密钥申请：`https://open.bigmodel.cn`（智谱开放平台）

两个注意点：

1. **完整 key 只在创建弹窗里显示一次**，列表页只显示打码形式，关掉就再也看不到。
   漏复制就删掉重建，当场保存（格式 `一串字符.另一串字符`，中间英文点别漏）
2. 设好后 Pi 会联网刷新出你账号真实可用的模型（`glm-4.7`、`glm-5.3` 等），
   推荐选 **`glm-4.7`**

#### 方案 C：已有订阅账号

在 Pi 里输入 `/login`，按提示选 ChatGPT Plus / Claude Pro / GitHub Copilot 等，
走 OAuth 授权，不用自己管钥匙。

#### 验证钥匙是否生效

```powershell
# 新开的窗口里执行，能打印出钥匙即生效
$env:ZAI_API_KEY        # 或 $env:AGNES_API_KEY

# 让 Pi 列出它当前能看到的全部模型
.\.pi-runtime\pi.cmd --list-models
```

| 报错 | 含义 | 处理 |
| --- | --- | --- |
| `401 无效的令牌` | 钥匙与站点/变量名不匹配 | 对照上表检查三者是否对齐 |
| `403 Insufficient quota` | 钥匙有效但余额为 0 | 去控制台领免费额度或充值 |
| `No models available` | 进程没读到环境变量 | 新开终端窗口再启动 Pi |

### 3.6 阶段六（可选）：启用记忆检索

不装也能正常用 Pi，只是没有语义搜索能力。**这一步是纯本地、完全免费的**，不需要 API 密钥。

```powershell
# 1. 启动 Qdrant 向量库
#    数据存在你的数据目录下，不在仓库里。
#    setup.ps1 第 6 步已自动生成 <数据目录>\docker-compose.yml 并尝试启动；
#    如果没起来，手动执行（把 C:\PiData 换成你自己的数据目录）：
cd "C:\PiData"
docker compose up -d
# 控制台: http://localhost:6333/dashboard

# 2. 装本地 embedding 模型（约 30MB）
ollama pull all-minilm:33m

# 3. 初始化记忆集合
```

## 5. 日常使用

### 5.1 启动

```powershell
cd 你要让它干活的目录
pi
```

Pi 会读取 `~/.pi/agent/AGENTS.md` 以及当前目录、各级父目录下的 `AGENTS.md`。

### 5.2 常用操作

| 想干什么 | 怎么做 |
| --- | --- |
| 换模型 | 会话内输入 `/model`，或按 `Ctrl+L` |
| 快速收藏常用模型 | `Ctrl+P` 循环切换 |
| 一次性提问（不进入交互） | `pi -p "总结这个项目"` |
| 列出可用模型 | `pi --list-models` |
| 回到历史某个节点继续 | `/tree` |
| 导出会话为 HTML | `/export` |
| 装一个扩展包 | `pi install npm:包名` 或 `pi install git:github.com/用户/仓库` |
| 查看已装包 | `pi list` / `pi update` |
| 改完配置生效 | `/reload` |

### 5.3 工具按需加载（这个包的核心机制）

`AGENTS.md` 里定义了工具预设，`/preset` 命令可以在运行时真正切换工具集：

| 你说的话里出现 | Pi 自动切换到 | 实际效果 |
| --- | --- | --- |
| 读、打开、长文档、大文件 | `/preset read` | 切为只读 + 搜索：`read, grep, find, ls` |
| 分析代码、依赖、结构、重构 | `/preset code` | 只读 + 可跑命令 |
| 规划、方案、设计、架构 | `/preset plan` | 纯只读，物理上改不了文件 |
| 查、搜索、找资料、链接 | `/preset web` | 追加 `web_search, web_fetch`（需 pi-web-access） |
| 写小说、写故事、章节 | `/preset write` | 四件套 + 注入去 AI 味写作规范 |
| 自动化、操作电脑、点击、截图 | `/preset computer` | 追加 `gui_*`（需 pi-computer-use） |
| 上下文大、需要压缩 | `/preset lean` | 追加 `ctx_*`（需 pi-lean-ctx） |
| 复杂任务、多工具协作 | `/preset full` | 8 个内置工具全开 |

任务做完会切回 `/preset fast`（四件套：`read, bash, edit, write`）。

**手动使用**：交互模式下直接输入 `/preset` 会弹出选择器；`/preset plan` 直接指定；
`Ctrl+Shift+U` 循环切换；也可以在启动时用 `pi --preset plan`。

**改预设**：编辑 `config\presets.json`，每个预设支持 `tools` / `model` /
`thinkingLevel` / `instructions` 四个字段。改完重新跑 `setup.ps1`，
或直接把文件复制到 `~/.pi/agent/presets.json`。

## 6. 已知限制与禁止事项

### 6.1 禁止事项

1. **不要推送到远端仓库。** 本项目所有者的既定规则：只做本地提交，不执行 `git push`。
   仓库已移除 `origin` 远端绑定，推送脚本与推送指引也已从包中删除。
2. **不要用 `git rm` 删除仓库内文件（务必牢记）。** 在 Git Bash / shell 里执行 `git rm`
   **会把父目录整个删掉**，即使传进去的路径本身是英文 —— 本仓库 `docs/` 下含中文文件名，
   已实测两次，两次都导致整个目录被清空（可从回收站或 `git restore` 复得）。
   要删文件请改用：先删工作区文件（Python `pathlib`），再 `git add -A` 让 Git 记录删除。
3. **涉及中文路径的文件操作一律用 Python（`pathlib`）完成**，不要走 shell 传参。
4. **不要跳过干跑直接正式安装。** 第 3.2 节的目的就是让你先确认数据目录。
5. **改了含中文的 PowerShell 脚本后必须存成 UTF-8 BOM。** 否则 PowerShell 5.1 读成乱码，
   而且是静默出错（脚本能过语法检查，运行时报奇怪的错）。`tests\verify.ps1` 会检查这一项。

### 6.2 已知限制

1. **扩展安装范围。** 安装脚本自动装 7 个扩展（npm 来源 6 个 + git 来源 1 个）。
   其余扩展需要手动装（`pi install npm:包名`）；
   规则文件里已逐项标注「脚本自动装 / 需手动装」，不必自行猜测。
2. **Qdrant 和 Ollama 需要单独起。** 脚本会尝试启动，但 Docker Desktop 没启动时会跳过。
3. **`-SkipPi` 模式下扩展不装。** 跳过 Pi 本体安装时，第 5 步的扩展安装也会跳过，
   需要扩展时得先装好 Pi 再手动 `pi install`。
4. **Pi 默认没有沙箱和权限确认。** 它会继承你当前用户的文件、进程、网络和凭证权限。
   官方建议：处理陌生代码或无人值守任务时，把 Pi 放进容器或虚拟机，只挂载需要的目录。
5. **网络要求**：安装阶段需要访问 npm 与 GitHub。7 个扩展里 6 个来自 npm、
   1 个（`pi-custom-packages`）来自 GitHub，比旧版（全部 `git clone`）可靠得多。
   国内网络建议先设镜像：`npm config set registry https://registry.npmmirror.com`。
   个别扩展装不上不影响 Pi 本体运行。
6. **`/preset` 机制已可用，但扩展工具取决于是否装了对应扩展。** 本仓库自带
   `extensions\preset.ts`（Pi 官方示例）与 `config\presets.json`，`setup.ps1` 会自动部署到
   `~/.pi/agent/extensions/preset.ts` 与 `~/.pi/agent/presets.json`。
   机制本身已在隔离环境实测通过（`--preset plan` 启动后工具集确实变为 `read, grep, find, ls`）。
   但预设里引用的**扩展工具**（`web_search`、`gui_*`、`ctx_*`）只有对应扩展装好后才会出现，
   未安装时 Pi 会自动过滤并给出提示，属预期行为，不是配置错误。
   验证方法：`pi --help` 中应出现 `--preset <value>` 一行（该 flag 由扩展动态注册）。

### 6.3 修复记录

**第一轮（2026-09-12）—— 部署阻塞点：**

| 问题 | 症状 | 修复方式 |
| --- | --- | --- |
| 规则文档只装进数据目录 | 装完 Pi 完全不知道那些规则，行为毫无变化 | 同时部署到 `~/.pi/agent/` |
| `settings.json` 被直接覆盖 | Pi 原有的 `theme`、`lastChangelogVersion` 被抹掉 | 改为合并写入，原文件自动备份为 `*.bak-时间戳` |
| 向量维度配置错误 | `embeddingDim` 写 1024 但脚本只装 384 维的模型，写入记忆必失败 | 统一为 `all-minilm:33m` + 384 维 |

**第二轮（2026-09-12）—— 一键安装缺口 + 扩展安装方式：**

| 问题 | 症状 | 修复方式 |
| --- | --- | --- |
| **缺"安装 Pi 本体"环节** | `setup.ps1` 假设 Pi 已装，第 7 步只打印一句「Pi 命令不可用」，整条链路从没真正跑通过 | 新增 `scripts\install-pi.ps1`（默认自包含安装），`setup.ps1` 增加第 2b 步调用它 |
| **扩展用 `npm install -g` 装** | 装完 Pi 根本发现不了（Pi 只认自己 `settings.json` 的 `packages` 列表），还污染全局 npm 目录 | 改用 `pi install npm:包名`，包装进配置目录的 `npm\` 并自动登记 |
| **扩展 git clone GitHub** | 国内网络下必然超时，整条安装流程卡死在第 5 步（已实测卡死一次） | 全部改为 npm 来源（这些包在 npm 上都有正式发布） |
| **无法隔离测试** | 装一次就写 `~\.pi\agent`、动全局 npm，很难做干净验证 | 全链路支持 `PI_CODING_AGENT_DIR` 重定向；新增 `-AgentDir` / `-SkipExtensions` / `-SkipPythonDeps` 开关 |
| **UAC 无条件提权** | 依赖齐全时也弹提权框，容易误触真实部署 | 新增 `-NoElevate`，只在确实需要装系统组件时才提权 |
| **首行取值导致版本误判** | `\| Select-Object -First 1` 提前掐断管道，`$LASTEXITCODE` 失真，Pi 明明可用却报"不可用" | 改为先收集输出数组再取首元素 |

**第三轮（2026-09-13）—— 补上 `/preset` 机制：**

| 问题 | 症状 | 修复方式 |
| --- | --- | --- |
| **`/preset` 只是空话** | `AGENTS.md` 承诺了 9 种工具自动切换，但机制所需的扩展与 `presets.json` 都不在包里，实际什么都不会发生 | 从 Pi 自带示例引入 `extensions\preset.ts`，新增 `config\presets.json`，`setup.ps1` 自动部署两者 |
| **预设名与实现不符** | 原表格承诺 `skill` / `sub` 两个预设，但 pi-skills-manager 与 pi-subagents 都不注册工具，无法通过工具开关实现 | 表格改为 9 个真实可用的预设，并逐项标注依赖哪个扩展 |
| **工具名靠猜** | 没人知道 Pi 到底暴露哪些工具，写预设只能瞎写 | 实测确认：8 个内置工具（`read/bash/powershell/edit/write/grep/find/ls`），默认只激活前 4 个；`verify.ps1` 新增工具名笔误校验 |

### 7.2 完全卸载

```powershell
# 1. 卸载 Pi 本体 —— 看你当初怎么装的：
#    默认方式（install-pi.ps1 自包含安装）：整个删掉安装目录即可，默认在 <仓库>\.pi-runtime

npm uninstall -g @earendil-works/pi-coding-agent

# 2. 删除配置（危险，会丢历史会话和记忆）
```
