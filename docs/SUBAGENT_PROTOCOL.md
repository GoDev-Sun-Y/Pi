# Pi 主/分支协作协议

## 何时使用 subagent

必须用 subagent 的场景：

- 任务大且真独立（可并行执行）
- 合并成本低（结果可直接汇总）
- 需要隔离上下文（避免污染主对话）

不用 subagent 的场景：

- 单文件读写、简单问答
- 需要主对话上下文参与的任务
- 串行依赖强、合并成本高

## 主对话职责

- 拆解任务（分解为独立子任务）
- 分配任务（spawn subagent）
- 汇总结果（整合各子任务输出）
- 最终决策（质量把控、冲突解决）

## 分支对话职责

- 执行子任务（专注单一目标）
- 返回结构化结果（文件路径、摘要、错误）
- 不依赖主对话上下文（独立运行）

## subagent 调度规则

| 场景 | 策略 |
| ------ | ------ |
| 独立并行任务 | async:true，等待 all |
| 串行依赖任务 | 顺序执行 |
| 结果需要合并 | 收集所有输出后汇总 |
| 需要隔离 | worktree:false（共享），worktree:true（隔离） |

## 结果返回格式

subagent 结果必须包含：

1. 状态（success/error/timeout）
2. 输出文件路径
3. 关键结论摘要
4. 错误信息（如有）

## 超时处理

- 单个 subagent 默认 30 分钟
- 超时后通知主对话
- 主对话决定继续或放弃

## 最佳实践

1. 子任务尽量独立，减少合并成本
2. 结果尽量结构化，便于汇总
3. 重要中间状态写 memory
4. 失败的任务先记录，再决定是否重试
